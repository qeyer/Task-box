# 目录决策参考

这些是决策示例，不是固定模板。只选择当前任务真正需要的部分。

## 视频剪辑

可能需要：

- `原始素材`：视频、音频、字幕、客户资料。
- `代理文件`：代理媒体确实会产生时才创建。
- `工程文件`：剪辑软件工程、自动保存。
- `字幕与文案`：有独立字幕或旁白流程时创建。
- `预览`：客户或内部审核文件。
- `最终成品`：确认后的成片和封面。

## 平面设计与社交图片

可能需要：

- `需求与参考`
- `素材`
- `设计稿`
- `预览`
- `最终导出`

只有一张参考图时，可直接放任务根目录，不必单建参考目录。

## 文案与研究

可能需要：

- `资料`
- `草稿`
- `定稿`

如果只是短文改写，任务根目录加 `定稿` 就可能足够。

## 数据分析

可能需要：

- `原始数据`
- `处理数据`
- `脚本`
- `图表`
- `报告`

原始数据与处理数据必须分开，避免覆盖源文件。

## 音频与播客

可能需要：

- `录音`
- `转写`
- `工程文件`
- `混音预览`
- `最终音频`

## 已有软件仓库

不要创建一份脱离仓库结构的代码副本。可创建：

- `docs/tasks/<任务名>/需求.md`
- `docs/tasks/<任务名>/验证记录.md`
- `docs/tasks/<任务名>/截图/`

代码、测试和配置仍修改原位置。

## 极简任务

最小有效结构可能只有：

```text
任务名/
├─ 任务说明.md
└─ 最终成品/
```

目录越少越好，但输入、过程和最终交付存在覆盖风险时必须分开。
