# 任务收纳

让每个独立任务有明确归属，用户能迅速找到最终成品并继续上次工作。只建立实际需要的目录。

用户授权执行任务后，自行判断是否使用本技能并完成必要收纳，不另行询问“是否使用 task-box”。讨论建议不触发创建或整理；只有文件归属无法确定或操作超出已有授权时才询问。

## 任务归属

- 用户指定的路径和结构优先；否则使用当前项目的既有任务资料目录，没有约定时在当前项目下建任务目录。
- 开始前只查看相关目录，按需读取 `工作文件/任务记录.md`；兼容旧版 `任务说明.md`，不遍历整台电脑。
- 按目标、客户或对象、素材和交付物判断是否续做；不能仅因类型相同或附近有任务说明就合并。
- 同一客户的不同会议、不同文章、不同批次各为独立任务；同一稿件的改版属于续做。
- 上下文能确定时直接复用；只有存在多个合理候选且会改变文件归属时才询问。

## 命名与最小结构

- 新任务默认用 `YYYY-MM-DD_对象_具体任务`，例如 `2026-09-07_张先生_厨房沟通纪要`。日期取执行环境本地日期。
- 同名但不同任务加简短区分词或递增后缀，不覆盖或静默合并。
- 一级目录统一使用 `素材`、`工作文件`、`预览`、`成品`、`归档`，仅创建实际需要的目录，不预建空文件夹。
- 新任务根目录默认只放文件夹。输入副本放素材，过程文件放工作文件，正式交付放成品；用户原始素材原地保留。
- 不再用“资料”“最终交付”“最终成品”“交付物”等同义名称另建一级目录。领域差异放到二级目录，用户指定结构及代码仓库原结构优先。
- 不确定如何分类时，按需读取 [目录参考](references/directory-decision-guide.md)。

## 续做与版本

- 续做有记录时先读当前成品、待办和关键决定；没有记录时结合对话和实际文件判断，不为补记录阻塞简单任务。
- 日常修改可更新本任务工作稿；已交付或用户确认的版本保留，后续交付用 `v02`、`v03` 等清晰版本号。
- 避免“最终版2”“最终最终版”。版本号与任务说明中的当前成品保持一致。
- 不把旧成品当输入反复复制；仅在需要区分历史交付时增加归档目录。
- 已明确授权的改稿无需每次再问；整理不构成删除、搬动或覆盖无关文件的授权。

## 可选任务记录与交付

一次性交付、少量文件且上下文清楚时不创建记录。跨次续做、多轮修改、存在待办或需要交接时，按需创建 `工作文件/任务记录.md`。
已有根目录 `任务说明.md` 继续复用，不自动移动、不重复建记录。记录仅包含：
- 目标与对象。
- 素材所在位置（可为外部路径，不复制敏感信息正文）。
- 状态：进行中、待确认或已完成。
- 当前成品的相对链接；尚未产生时写“尚未生成”，不预称完成。
- 尚未解决的问题、下一步和必要的关键决定。

有重要变更、暂停或交付时更新已有记录，不逐条记录工具操作。成品链接相对于记录所在目录，例如 `../成品/报告_v02.docx`。
完成后提供最终成品链接；多个任务共存时明确本次任务目录。
无需为普通收纳展示计划 JSON 或长篇目录解释。

## 执行方式

- 简单目录可直接建立，记录按需创建，不强制运行脚本。
- 脚本计划的 `create_note` 默认是 `false`；需要任务记录时设为 `true`，生成 `工作文件/任务记录.md`。
- 需要批量创建子目录和路径校验时，使用 [计划示例](references/example-plan.json) 与 `scripts/create_workspace.py`。
- 脚本只负责新建，拒绝同名目录；续做直接更新现有任务，不重新运行创建器。
- JSON 使用 UTF-8，放在当前任务的临时位置或当前已授权工作目录；完成创建后删除本次临时计划。
- Windows：`python scripts/create_workspace.py "<计划文件绝对路径>"`；macOS/Linux 使用 `python3`。脚本路径相对于技能目录。

## 已有仓库与整理边界

- 源码、测试和配置保持仓库原结构；任务资料目录只收纳需求、素材副本、截图、验证记录和导出物。
- 本任务新增过程文件放入本任务目录；不要修改其他支线。
- 对已有散乱文件，只有用户要求整理时才移动，并先确认其归属；不按扩展名把不同任务混在一起。
- 不自动删除原始素材或历史交付。清理仅针对明确可丢弃的本次临时文件。
